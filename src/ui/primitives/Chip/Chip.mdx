# Chip

Chip renders a small interactive token — a filter, a selection, a removable tag, or a clickable category — that the user can add to, remove from, or select within a collection. Reach for it when each token can act on its own (toggle a filter, remove a tag) and you want the collection to read as a row of pills.

## When to use

- Use Chip for a filter token the user can apply or remove inline — search filters, tag selections, applied criteria above a result list.
- Use Chip with `onRemove` for tokens the user added and can dismiss — selected attachments, applied tags on a card, mentioned people.
- Use Chip with `selected` for "pick one or many from a set" patterns where Radio or Checkbox would feel too form-like — interest tags, category pickers, filter toggles.
- Use `variant="filled"` (or `selected={true}`) for the on / chosen state and `variant="outlined"` or `variant="default"` for the off / unselected state.

## When not to use

- Use `Badge` for a non-interactive status or category label — Badge is a label, Chip is a control.
- Use `Button` for a one-off action that belongs to a row but doesn't live inside a collection of similar tokens.
- Use `MultiSelect` when the option set is long enough that listing all chips would crowd the page — a dropdown is the right affordance there.
- Avoid Chip for binary on / off settings unrelated to a collection — use `Switch` or `Checkbox`.

## Anatomy

Chip renders in source order: the `label` (the `children` content — the chip's name or value), an optional `count` sub-badge, and, when `onRemove` is provided, a trailing `remove button` (an `X` icon) — all inside the same chip surface. When both `onClick` and `onRemove` are present, the click and the remove are two distinct hit targets with separate accessible names.

### Count sub-badge

The `count` prop renders a count pill at the end of the chip — the filter-bar pattern (`Câmara 12`, `Tramitando 340`). The pill **inverts with the chip surface** so it always contrasts: a brand pill on neutral chips (`default` / `outlined`), a light pill on brand chips (`selected` or `variant="filled"`). `count={0}` is a legitimate value and renders `0`; omit the prop for "no count". On interactive chips the number is folded into the accessible name (`"Câmara, 12"`) so AT users hear it once; pass an explicit `aria-label` to override that phrasing. `count` is forbidden in the `asChild` form (the consumer composes the node).

## Polymorphic chip via `asChild`

`asChild` (issue #154) projects the chip frame onto a single child element — typically a framework Link — instead of rendering the standard `<div>` + inner-button structure. The collapsed node **is** the chip: no inner button, no X. The pattern is what enables server-rendered, zero-JS filter chips in Next/RSC consumers (one `<a href>` per chip, native navigation, prefetch preserved).

```tsx
<Chip asChild variant="filled" selected>
  <Link href="/filtros/em-votacao" prefetch aria-current="page">
    Em votação
  </Link>
</Chip>
```

### Forbidden in this form (enforced by TypeScript)

| Prop       | Why                                                                                                                                                                                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `onClick`  | The child element owns activation. Pass the handler (or `href`) on the child Link / button itself.                                                                                                                                                                                  |
| `onRemove` | The collapsed node has no slot for an X button. Use the standard (non-`asChild`) form when removal is required.                                                                                                                                                                     |

### A11y responsibility transfer (read before adopting)

The standard Chip is carefully shaped to avoid two axe failures (`aria-required-parent`, `nested-interactive`). `asChild` defers that shape entirely to the consumer's child. **You inherit responsibility for:**

- **Role**: the child's native role is what AT users hear. An `<a href>` reads as a link; a `<button>` reads as a button. The chip's `selected` styling does NOT change this.
- **Selected state**: `selected` still applies the visual `bg-surface-brand-strong` + `border-line-brand`. It does **NOT** emit `aria-pressed` — a link is not a two-state control. Communicate the selected route to AT users with `aria-current="page"` on the child Link.
- **Focus**: the child carries the focus ring. Chip does not attach `focus:ring-*` utilities to the projected node — if the child is a Link without a focus style, supply one explicitly.
- **Disabled**: `aria-disabled` is forwarded, but `disabled` on `<a>` does NOT block navigation. Gate `href` upstream when truly blocking is required.

The forbidden `onClick` / `onRemove` are enforced at the TypeScript level (discriminated union) — the compiler rejects them rather than failing silently at runtime.

## Accessibility

Chip's accessibility shape depends on which interactions are wired. A non-interactive Chip (no `onClick`, no `onRemove`) renders as a labelled token with no role — content is announced inline.

When `onClick` is provided, the chip surface becomes interactive with an explicit `aria-label` describing what the click does (selecting a filter, applying a tag). Keyboard activation uses Enter / Space.

When `onRemove` is provided, the trailing `X` is a separate `<button>` with its own `aria-label="Remove <label>"` so screen readers identify the destructive affordance distinctly from the chip itself. The user can Tab to the remove button independently of the chip surface.

When both `onClick` and `onRemove` are present, the focus order is chip → remove button. Activating the chip toggles selection; activating the remove button removes the chip from the collection. Each surface carries its own accessible name; the chip's label text is not enough on its own — set `aria-label` explicitly when the click action would not be obvious from the visible text.

For a collection of chips representing a single multi-select question (a row of filter chips), wrap the group in a container with `role="group"` and `aria-label` describing the question, so the collection's purpose is announced before each chip's individual label.
