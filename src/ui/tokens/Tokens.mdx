# Design Tokens

Design tokens are the foundational visual design atoms of the design system. They represent design decisions about colors, spacing, typography, shadows, and more. Using tokens ensures consistency across all components and makes it easy to maintain and update the design system.

## Overview

The design token system uses a **Factory Pattern** to create type-safe tokens consistently. All tokens follow a standardized structure and can be accessed through helper functions.

## Color Tokens

Color tokens provide semantic color values with support for light and dark themes.

### Color Roles

- `primary` - Primary brand color
- `secondary` - Secondary brand color
- `success` - Success states and positive actions
- `warning` - Warning states and caution
- `error` - Error states and destructive actions
- `info` - Informational content
- `neutral` - Neutral grays for text and backgrounds

### Color Shades

Each color role has four shades:

- `light` - Lightest variant
- `DEFAULT` - Default/main color
- `dark` - Darkest variant
- `contrast` - Contrast color for text on colored backgrounds

### Usage

```tsx
import { getColorClass } from "@fabio.caffarello/react-design-system";

// Background color
const bgClass = getColorClass("primary", "DEFAULT", "bg"); // 'bg-brand-primary-500'

// Text color
const textClass = getColorClass("error", "dark", "text"); // 'text-red-600'

// Border color
const borderClass = getColorClass("neutral", "DEFAULT", "border"); // 'border-gray-300'
```

### Semantic Brand Foreground

The brand foreground vocabulary exposes two roles:

- `text-fg-brand` — Default brand foreground. Use for brand-colored
  text/icons in their idle/neutral presentation (e.g., a brand-colored
  link in body copy, the brand logotype).
- `text-fg-brand-emphasis` — Emphasis variant of brand foreground.
  Used for selected/active states where the brand color is intensified
  relative to its default (e.g., the icon/label of the currently
  active item in a navbar).

Light theme uses `brand-primary-500` for `fg-brand` and `brand-primary-600`
for `fg-brand-emphasis` (darker). Dark theme uses `brand-primary-400` for
`fg-brand` and `brand-primary-300` for `fg-brand-emphasis` (lighter),
preserving the "emphasis is more contrasted against the surface"
relationship in both modes.

The secondary brand foreground mirrors this structure:

- `text-fg-brand-secondary` — Default secondary brand foreground
  (`brand-secondary` scale). Use for secondary-branded text/icons in
  their idle/neutral presentation.
- `text-fg-brand-secondary-emphasis` — Emphasis variant of secondary
  brand foreground. Intensified shade for selected/active states in
  secondary brand contexts.

Same shade relationship as primary: `brand-secondary-500/600` (light,
default/emphasis) and `brand-secondary-400/300` (dark, default/emphasis).

The `brand-primary` and `brand-secondary` scales are the design system's
own primitives, declared in `src/styles/primitives/brand.css`. They are
the reskin surface — consumers redefine them in their own `:root` or
`@theme`, and every semantic token cascades automatically. Tailwind
primitives (`indigo`, `pink`, `cyan`, ...) stay honest to their official
Tailwind v4 HEX and are **not** the reskin surface.

### Status Neutral

`bg-status-neutral` completes the status indicator family
(`bg-success` / `bg-warning` / `bg-error` / `bg-info` / `bg-status-
neutral`) used by `Dot`, status `Badge`, online presence indicators,
and similar components. Use it for the "offline / inactive / no
specific status" variant when a component's CVA already covers the
four feedback states with semantic tokens.

Light theme: `slate-500`. Dark theme: `slate-400` (one shade lighter,
mirroring the `success/warning/error/info` flip pattern).

Distinct from `text-fg-*` (which is for foreground text/icons) and
`bg-line-*` (which is for visual lines like dividers/marks). Status
indicators are filled dots/badges representing a state — their own
semantic family.

### Scrim and Tint-hover (theme-agnostic)

Two translucent black tokens that do **not** flip between light and
dark themes. They exist to preserve a darkening function that must
stay dark regardless of theme.

- `bg-scrim` — Backdrop veil at 50% black opacity. Use behind a
  modal, drawer, command palette, or any overlay that needs to focus
  attention by darkening the page beneath it. Scrim is _theme-
  agnostic by design_: a "lightening" backdrop in dark mode would not
  serve the same focusing function. Distinct from `bg-surface-
overlay`, which is the _container_ of the overlay (white in light,
  slate-800 in dark — flips with theme); scrim is the _veil between
  the page and the overlay container_.
- `bg-tint-hover` — Translucent state layer at 10% black opacity for
  hover feedback on buttons embedded in elements whose background
  color is variable (e.g., a remove button inside a brand-filled
  chip vs the same button inside a neutral chip). Theme-agnostic
  because the translucency works over any underlying surface in any
  theme. Distinct from `bg-surface-hover`, which is a _solid neutral
  color_ (slate-50 in light, slate-800 in dark) used for hover on
  flat backgrounds; tint-hover preserves the surface color showing
  through, just darkened.

If a future state needs a similar translucent layer (pressed, focus,
selected), use the same naming family: `--color-tint-pressed`, etc.

## Spacing Tokens

Spacing tokens are based on a 4px base unit, providing consistent spacing throughout the design system.

### Spacing Scale

The scale is based on a 4px base unit. Half-steps (`0.5`, `1.5`, `2.5`, `3.5`)
exist to cover micro-spacing in fine UI controls (badge padding, switch
geometry, separator thickness). Without them components would reach for raw
Tailwind `p-1.5` / `gap-2.5` / etc. and bypass the scale.

- `none` - 0px
- `0.5` - 2px _(half-step)_
- `xs` - 4px
- `1.5` - 6px _(half-step)_
- `sm` - 8px
- `2.5` - 10px _(half-step)_
- `md` - 12px
- `3.5` - 14px _(half-step)_
- `base` - 16px
- `lg` - 24px
- `xl` - 32px
- `2xl` - 40px
- `3xl` - 48px
- `4xl` - 64px
- `5xl` - 80px
- `6xl` - 96px

### Usage

```tsx
import { getSpacingClass } from "@fabio.caffarello/react-design-system";

// Padding
const paddingClass = getSpacingClass("md", "p"); // 'p-3'

// Margin
const marginClass = getSpacingClass("lg", "mx"); // 'mx-6'

// Gap
const gapClass = getSpacingClass("base", "gap"); // 'gap-4'
```

## Typography Tokens

Typography tokens define font sizes, weights, and line heights for consistent text styling.

### Font Sizes

- `2xs` - 10px _(micro-text: badge counters, mini chips)_
- `xs` - 12px
- `sm` - 14px
- `base` - 16px
- `lg` - 18px
- `xl` - 20px
- `2xl` - 24px
- `3xl` - 30px
- `4xl` - 36px
- `5xl` - 48px
- `6xl` - 60px

### Font Weights

- `light` - 300
- `normal` - 400
- `medium` - 500
- `semibold` - 600
- `bold` - 700

### Usage

```tsx
import { getTypographyClasses } from "@fabio.caffarello/react-design-system";

// Heading styles
const h1Classes = getTypographyClasses("h1"); // 'text-4xl leading-tight font-bold'
const h2Classes = getTypographyClasses("h2"); // 'text-3xl leading-tight font-bold'
const bodyClasses = getTypographyClasses("body"); // 'text-base leading-relaxed font-normal'
```

## Animation Tokens

Animation tokens define consistent timing and easing for transitions and animations.

### Animation Durations

- `fast` - 150ms
- `base` - 200ms
- `slow` - 300ms
- `slower` - 500ms

### Easing Functions

- `ease-in` - Slow start, fast end
- `ease-out` - Fast start, slow end
- `ease-in-out` - Slow start and end, fast middle
- `spring` - Spring-like bounce effect

### Usage

```tsx
import {
  getAnimationClass,
  getTransitionClass,
} from "@fabio.caffarello/react-design-system";

// Animation classes
const animClass = getAnimationClass("base", "ease-in-out"); // 'duration-200 ease-in-out'

// Transition classes
const transitionClass = getTransitionClass(
  ["color", "background-color"],
  "base",
); // 'duration-200 ease-in-out'
```

## Z-Index Tokens

Z-index tokens provide consistent layering for overlapping elements.

### Z-Index Layers

- `base` - 0 (normal content)
- `dropdown` - 1000 (dropdown menus)
- `sticky` - 1020 (sticky headers)
- `fixed` - 1030 (fixed elements)
- `modal-backdrop` - 1040 (modal overlays)
- `modal` - 1050 (modal dialogs)
- `popover` - 1060 (popovers)
- `tooltip` - 1070 (tooltips)
- `toast` - 1080 (toast notifications)

### Usage

```tsx
import { getZIndexClass } from "@fabio.caffarello/react-design-system";

const zIndexClass = getZIndexClass("modal"); // 'z-[1050]'
```

### Opacity Values

- `0` - Fully transparent
- `5` - Very light overlay
- `10` - Light overlay
- `25` - Quarter opacity
- `50` - Half opacity
- `75` - Three-quarter opacity

### Usage

## Component-Scoped Tokens

Some dimensions are anatomical to a single component and would pollute the
global scale if added there. They live in their own token file under
`src/ui/tokens/<component>.ts` and are exported alongside the global tokens.

The rule of thumb: a value lives in the global spacing scale **only if**
multiple components reach for it. One-off geometry (a switch's track width,
a sidebar's nested-indent ladder) stays in component-scoped tokens.

### Switch

The switch's track / thumb / on-state translation per size variant.
Values are tied to the visual anatomy of the control — not to general spacing.

- `sm` — 36 × 20 track, 16 × 16 thumb, translate 16
- `md` — 44 × 24 track, 20 × 20 thumb, translate 20
- `lg` — 56 × 28 track, 24 × 24 thumb, translate 28

```tsx
import { getSwitchClasses } from "@fabio.caffarello/react-design-system";

const { track, thumb, translate } = getSwitchClasses("md");
// track     -> "w-11 h-6"
// thumb     -> "w-5 h-5"
// translate -> "translate-x-5"
```

See [`SIDEBAR_TOKENS`](#z-index-tokens) above — sidebar carries its own

## Best Practices

### ✅ Do Use Tokens

```tsx
// ✅ Good - Using tokens
import {
  getColorClass,
  getSpacingClass,
  getRadiusClass,
} from "@fabio.caffarello/react-design-system";

const className = `
  ${getColorClass("primary", "DEFAULT", "bg")}
  ${getSpacingClass("md", "p")}
  ${getRadiusClass("lg")}
`;
```

### ❌ Don't Use Hardcoded Classes

```tsx
// ❌ Bad - Hardcoded classes
const className = "bg-indigo-500 p-3 rounded-lg";
```

## Migration Guide

When refactoring components, replace hardcoded classes with tokens:

1. **Colors**: `bg-gray-500` → `getColorClass('neutral', 'DEFAULT', 'bg')`
2. **Spacing**: `p-4` → `getSpacingClass('base', 'p')`
3. **Shadows**: `shadow-lg` → `getShadowClass('lg')`
4. **Radius**: `rounded-md` → `getRadiusClass('md')`
5. **Borders**: `border-2` → `getBorderWidthClass('medium')`

Run `npm run audit:tokens` to find hardcoded classes in your components.
