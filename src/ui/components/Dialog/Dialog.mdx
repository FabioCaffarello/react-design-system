# Dialog

Dialog is a compound dialog component with explicit slots for the trigger, content, header, title, description, footer, and close button — the consumer assembles the parts to shape the dialog they need. Reach for it for interactive overlays that need richer composition than `Modal`'s flat-prop API (custom action layouts, multi-paragraph descriptions, embedded forms, AlertDialog variants).

## When to use

- Use Dialog for interactive overlays that need composed parts — confirmation flows with primary + secondary + destructive buttons, multi-paragraph explanations with custom layouts, embedded forms or surveys.
- Use the compound API so the parts are wired correctly without prop boilerplate — `Dialog.Title` binds to `aria-labelledby` automatically, `Dialog.Description` binds to `aria-describedby`, `Dialog.Close` triggers the close handler.
- Use controlled mode (`open` + `onOpenChange`) when external state drives visibility — programmatic opens, multi-instance coordination, persisted state.
- Use the AlertDialog variant for destructive confirmations — it carries different ARIA semantics (`role="alertdialog"`) so screen readers signal the severity.

## When not to use

- Use `Modal` for the simple "title + body + footer with showCloseButton" shape — Modal's flat props cover the common case without compound boilerplate.
- Use `Drawer` for side panels that slide in from an edge instead of centering on the page.
- Use `Popover` for inline tooltips or compact contextual content anchored to a trigger — Dialog dominates the viewport, Popover floats next to its trigger.

## Anatomy

Dialog is composed from a deep compound API. The root `Dialog` mounts a context provider carrying open state and the generated `aria-labelledby` / `aria-describedby` IDs. `Dialog.Trigger` wraps the element that opens the dialog (typically a `Button`) and wires `aria-haspopup="dialog"` + `aria-expanded`. `Dialog.Content` is the portaled panel with `role="dialog"` containing the rest. Inside `Dialog.Content`: `Dialog.Header` carries the top region with `Dialog.Title` (the heading, wired to `aria-labelledby`) and optional `Dialog.Description` (the explanatory text, wired to `aria-describedby`). The body content sits between header and footer. `Dialog.Footer` carries the bottom action row. `Dialog.Close` is the explicit dismiss affordance (visible close button or a button inside the footer) that triggers `onOpenChange(false)`.

## Accessibility

Dialog implements the WAI-ARIA Dialog pattern. `Dialog.Content` carries `role="dialog"` with `aria-modal="true"`, `aria-labelledby` pointing at `Dialog.Title`'s generated ID, and `aria-describedby` pointing at `Dialog.Description`'s generated ID when present. The wiring is automatic — the consumer composes the parts, the provider connects them.

Focus moves to the first focusable element inside `Dialog.Content` on open (often `Dialog.Close` or the first form control) and returns to the trigger on close. While open, focus is trapped inside the dialog — Tab cycles only within the dialog, the underlying page is inert.

`Dialog.Close` is a native `<button>` with an explicit `aria-label="Close dialog"` when it renders as the icon-only variant; when used inside `Dialog.Footer` as a labelled button, the visible label provides the accessible name. ESC closes the dialog by default; outside-click closes it unless `closeOnOverlayClick={false}` is passed.

Body scroll locks while the dialog is open so the underlying page does not move under the user. The lock is automatic; do not duplicate it in consumer code.

The AlertDialog variant changes `role="dialog"` to `role="alertdialog"` — assistive tech announces the severity differently, and screen-reader users hear a stronger signal that the dialog requires their attention. Use it only for destructive confirmations (delete, sign out from all sessions, irrevocable actions); overusing the role dilutes the signal.

For dialogs that render forms, set the form's submit button as the default focus target so Enter inside any field submits the form — the dialog's focus trap keeps the keyboard pattern intact.
