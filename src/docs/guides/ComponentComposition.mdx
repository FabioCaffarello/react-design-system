# Component Composition

This design system is built in three layers. Composing across the layers is how features get assembled — and the layer boundary tells you what is allowed to depend on what.

## The three layers

- **Primitives** (`src/ui/primitives/`) — `Button`, `Input`, `Text`, `Badge`, `Avatar`, and 18 others. Indivisible. A primitive never imports from `components/` or `layouts/`.
- **Components** (`src/ui/components/`) — `Modal`, `Form`, `Card`, `Drawer`, `Table`, and 32 others. Composed from primitives. A component imports from `primitives/` freely; never from `layouts/`.
- **Layouts** (`src/ui/layouts/`) — `Container`, `Stack`. Structure only. Layouts import primitives only; never `components/`.

These rules are enforced in `.claude/rules/components.md`. The point is one-way flow: a primitive change can't accidentally break a layout, because layouts can't see primitives' siblings, and components can't see layouts at all.

## Patterns

### Form field — primitives composed by the consumer

A labeled, validated input is three primitives stacked vertically. The DS does not ship a `FormField` wrapper; the consumer composes it once and reuses it.

```tsx
import {
  Label,
  Input,
  ErrorMessage,
  Stack,
} from "@fabio.caffarello/react-design-system";

function EmailField({
  value,
  error,
  onChange,
}: {
  value: string;
  error?: string;
  onChange: (v: string) => void;
}) {
  return (
    <Stack spacing="xs">
      <Label htmlFor="email">Email</Label>
      <Input
        id="email"
        type="email"
        value={value}
        onChange={(e) => onChange(e.target.value)}
        aria-invalid={!!error}
      />
      {error && <ErrorMessage>{error}</ErrorMessage>}
    </Stack>
  );
}
```

`Label`, `Input`, and `ErrorMessage` are independent primitives. `Stack` (layout) handles vertical rhythm via `spacing` — one of `xs | sm | md | base | lg | xl | 2xl`. The composed wrapper lives in app code, not in the DS, because field shape varies per consumer (some need help text, icons, async validation hints) and the wrapper API would calcify if pulled into the system.

### Modal — component holding consumer content

```tsx
import {
  Modal,
  Button,
  Text,
  Stack,
} from "@fabio.caffarello/react-design-system";

function DeleteConfirmation({
  isOpen,
  onClose,
  onConfirm,
}: {
  isOpen: boolean;
  onClose: () => void;
  onConfirm: () => void;
}) {
  return (
    <Modal isOpen={isOpen} onClose={onClose} title="Delete project">
      <Stack spacing="md">
        <Text>This action cannot be undone.</Text>
        <Stack spacing="sm" direction="row">
          <Button variant="ghost" onClick={onClose}>
            Cancel
          </Button>
          <Button variant="error" onClick={onConfirm}>
            Delete
          </Button>
        </Stack>
      </Stack>
    </Modal>
  );
}
```

`Modal` (component) handles overlay, focus trap, and ESC dismissal — consumers provide body content via `children`. Buttons use `variant="error"` for the destructive action; the full variant union is `primary | secondary | error | outline | ghost | iconOnly` and sizes are `sm | md | lg` (default `md`).

### Page layout — layouts plus components, never the other way around

```tsx
import {
  Container,
  Stack,
  Card,
  Text,
  Button,
} from "@fabio.caffarello/react-design-system";

function ProductPage() {
  return (
    <Container maxWidth="lg">
      <Stack spacing="lg">
        <Stack direction="row" spacing="md">
          <Text variant="heading">Products</Text>
          <Button variant="primary">New product</Button>
        </Stack>
        <Card padding="large">{/* product list */}</Card>
      </Stack>
    </Container>
  );
}
```

`Container` caps width (`sm | md | lg | xl | 2xl | full`). `Stack` handles spacing/direction. `Card` provides surface elevation with `padding` (`none | small | medium | large`) and `variant` (`default | hover | selected`). The layer order in the JSX mirrors the layer order in the system: a Container wraps a Stack wraps a Card.

## What not to compose

- **Do not modify a DS component by overriding its semantics with `className`.** If a `Card` needs a hover affordance, use `variant="hover"`; if it needs a different padding, pass the prop. Reaching for `className="!p-2"` to defeat an existing prop is a smell — either the existing prop is wrong (raise it) or your need is wrong (rethink).
- **Do not invent layer-crossing imports.** A primitive that imports from `components/` is a sign the primitive is wrong, not that the rule is wrong. Move logic up, not down.
- **Do not build a DS component just because three primitives appear together.** Composition lives in app code by default. The bar for promoting a composition into the DS is "used identically in ≥3 places and the API is stable enough that the next consumer won't need to fork it."
